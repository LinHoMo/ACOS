## 3. 两臂设计（单变量隔离）

```text
Control   = --serialization-teaching            （S1 配置：旧 execution binding，env 容忍、不注入）
Treatment = --serialization-teaching --structured-inputs （S3 配置：inputs 注入 + inputs 教学 + env 拒绝）
```

- 两侧均保留序列化教学（H-S 已证明），使**唯一自变量** = Structured Inputs Package；Control 不会因 code-as-map 编译崩盘，执行层对比不被编译层污染。
- 样本量：**Control ×10 + Treatment ×10**（`--runs 10`）。
- `--start-index` 默认 1；trace 覆盖保护沿用探针既有逻辑（拒绝覆写）。

## 4. 指标

沿用 v0.4 四层矩阵（Compile/Contract/Execute/Adequacy）+ v0.4 指标，新增/明确：

| 指标 | 定义 | 分母 |
|---|---|---|
| serialization_failure_rate | code-as-map 编译失败 runs | total runs（空响应除外，空响应单列） |
| env_failure_rate | env 类失败 runs（Control：运行时 `NameError: env`；Treatment：`InvalidPythonBinding` 未修复） | 进入执行层（final plan 含 execute_python）的 runs |
| env_persistence_rate | final plan 代码仍含 env 引用的 runs | 同上 |
| **binding_adoption_rate** | final plan 的 execute_python 步骤中实际采用 `inputs[...]` 的比例（run 级：该 run 的 python 步骤中至少一处 `inputs[`；步骤级：`inputs[` 步骤数 / 总 python 步骤数） | 含 execute_python 步骤的 runs（run 级）/ 总 python 步骤（步骤级） |
| repair_rate / repair_attempts | 平均 repair 次数 | runs |
| latency | `total_wall_ms` 均值/中位数 | runs |
| **token_cost** | 每 run prompt+completion tokens 之和（acos-llm 新增 usage 捕获） | runs |
| **empty_response_rate** | `initial_raw_response == ""` 的 runs（模型层空响应，独立失败类） | total runs |

**分母规则**：分母为 0 → N/A；空响应 runs 从绑定类指标（env_*/binding_adoption）分母中**剔除**，单独报告为 failure class（防止 `env_failure=0` 只因模型没执行）。

## 5. R2 判定门（n=10，全部满足才判 H-E SUPPORTED）

1. **structured-input adoption 明显提高**：`binding_adoption_rate(Treatment) ≥ 0.8`，且 `binding_adoption_rate(Control) ≤ 0.2`（对比可见）；
2. **env_failure_rate 显著下降**：`env_failure_rate(Treatment) ≤ 0.2` 且 `env_persistence_rate(Treatment) ≤ 0.2`（n=10 → 失败 ≤ 2），且 `env_failure_rate(Control) ≥ 0.5`（对照组缺陷可观测）；
3. **Execute rate 不下降**：`Execute(Treatment) ≥ Execute(Control) − 1`；
4. **Adequacy 无反向退化**：`Adequacy(Treatment) ≥ Adequacy(Control)`；
5. **空响应门槛**：`empty_response_rate(Treatment) < 50%`（≥5/10 空响应 → H-E **NOT JUDGABLE**，报告空响应现象并分析原因）。

不满足任一 → H-E **INCONCLUSIVE**（维持 v0.4 判定）。辅助统计：env_failure 2×2 Fisher exact 检验（n=10 下为描述性指标，不作硬门槛）。

## 6. 工程改动（最小化，全部为实现 metadata/可靠性所需）

### 6.1 `acos-llm`（crates/acos-llm/src/lib.rs）

- 新增 `ACOS_LLM_TEMPERATURE`（`Option<f64>`，默认不发送/None；R2 harness 固定 0.0）
- 新增 `ACOS_LLM_TIMEOUT_SECONDS`（`Option<u64>` → reqwest `Client::builder().timeout()`；当前无超时，挂起请求可无限等待）
- 新增 token usage 捕获：`ChatResponse.usage: TokenUsage`；Anthropic `MessagesResponse.usage`（input/output tokens）与 OpenAI `ChatCompletionsResponse.usage`（prompt/completion/total tokens）统一映射
- 兼容：未设置 temperature/timeout 时行为与现状一致；usage 缺失时记 0

### 6.2 `p1-5b-probe`（crates/acos-cli/src/bin/p1-5b-probe.rs）

- **修复日期换算 bug**：`days_to_date()` 改用正确 proleptic Gregorian 历法换算（civil_from_days 算法，无新依赖）；`iso_timestamp()` 输出真实 UTC 日期（v0.4 的 09-05/06 时间戳即此 bug 产物，非主机时钟偏差）
- trace 新增顶层 `metadata` 块（§7 模板），全部由程序自动填充（`ACOS_EXP_COMMIT` / `ACOS_EXP_CLOCK_SANITY` / `ACOS_LLM_*` 环境变量 + OS/epoch 秒）；`key_present` 由 key 长度判定，`raw_key_persisted` 恒为 false
- 启动前 provider 预检：一次最小 completion（`complete("reply with OK")`）→ `metadata.limits.quota_status`；失败记录状态码
- 运行中观测：从 `initial_error` / `final_error` 提取 4xx/5xx 状态码 → `metadata.limits.observed_events`（402/429/401/500 等）
- 记录每 run `timing.total_wall_ms` + 汇总 `usage`（来自 compiler 的 LLM 调用）

### 6.3 新 harness `formal-eval-v0.4-r2.ps1`

- 参数：Task/GT/ControlDir/TreatmentDir/ModelRuns(=10)/Temperature(=0.0)/MaxTokens(=32768)/TimeoutSeconds(=600)/Model/Provider
- 运行前：设置上述环境变量 + `ACOS_EXP_COMMIT`（`git rev-parse HEAD`）+ 时钟预检（`w32tm /stripchart /computer:time.windows.com /samples:1` 解析偏移；失败降级 `clock_sanity_check=unverified`）
- 执行：Control（`--serialization-teaching`）×10 → Treatment（`--serialization-teaching --structured-inputs`）×10
- 聚合：层矩阵、全部指标、binding_adoption_rate、token_cost、empty_response；按 §5 判定门输出 verdict
- 产物：`summary-r2.md` + `experiment-metadata.json`（会话级固定条件快照）
- **不修改** v0.4 harness / 探针既有参数语义（新增字段与参数均向后兼容）

### 6.4 文档

- 修订 `experiments/p1-5b-cognitive-program-discovery/summary-v0.4.md` 的 `timestamp_note.interpretation`：`"Host clock skew suspected"` → `"Probe date-conversion bug (days_to_date approximation); raw trace timestamps preserved"`（仅文档，不触碰任何 trace 文件）
